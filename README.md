# ACF JSON CSV Integrator

An integrated tool to export and import ACF (Advanced Custom Fields) flexible content and repeaters seamlessly as JSON-formatted strings via CSV.

### 1.0.37 (2026-09-02)

- 修正: CSVインポート時、画像取得前に移行先ドメインへ置換して404になる問題を修正。JSON内URLの正規化、リダイレクト、2xxレスポンスにも対応。

### 1.0.27 (2026-06-12)
dev環境（マルチサイト 001_development）でも検証済み。「マルチサイトだから柔軟コンテンツが入らない」は誤りで、実際はターム379に正しく入っていた（確認していたのは別ターム174）。画像は移行元URL未指定が原因だった。

- 新機能: エクスポートCSVに移行元サイトURL（`_ajci_origin` 列）を自動埋め込み。インポート時にこの列を自動で読み取って画像ID解決に使用するため、「移行元サイトURL」の手入力が不要に（手入力した場合はそちらを優先）。投稿・ターム・オプションページの3種すべてのエクスポートに対応。
- 不具合修正: タームインポートで、CSVのスラッグが移行先の別タームで使用済みの場合（例: `kitchen` が既存ターム「キッチン」で使用中）、`duplicate_term_slug` エラーで名前・説明・親の更新まで丸ごと失敗していた問題を修正。既存スラッグを維持して名前等のみ更新し、警告を表示するように変更。

### 1.0.26 (2026-06-11)
実サーバー（003-shiptraining.jp テスト環境）でターム／オプションページ／投稿の3種CSVをフルインポート検証し、柔軟コンテンツ・画像が100%取り込まれることを確認済み。

- 重大な不具合修正（画像が入らない問題の本丸）: 画像の新規取り込み時に `wp_insert_attachment` へ `ID`（旧ID）を渡していたため、存在しないIDでは「既存投稿の更新」と解釈されて常に失敗（0）していた問題を修正。`import_id`（推奨ID）として渡すことで、IDが空いていれば旧IDのまま、埋まっていれば新IDで正しく登録されるように変更。
- 重大な不具合修正: 同一IDのアタッチメントが移行先に存在する場合の健全性チェックを追加。DBレコードだけあって実ファイルが無い「壊れたアタッチメント」（クローン環境で頻発）を従来はそのまま採用してしまい、管理画面で画像が空に見えていた。実ファイルの存在を確認し、壊れている場合は `_source_url` メタから自動再ダウンロードして**その場で修復**（ID維持）するように変更。
- 改善: 移行元URLの候補を複数化（`getImportOriginCandidates`）。ユーザー指定URL → `_source_url` メタ由来 → guid 由来の順で自動的に複数の移行元を試行。移行元の指定が間違っていても、過去のインポート履歴から本来の画像元（例: 本番サイト）を見つけて解決できる。
- 改善: REST API が無効（`rest_disabled`）の判定を移行元ごとにキャッシュし、無駄なAPIリクエストを削減。スクレイピングフォールバックの正規表現に og:image を追加し、無関係なページから誤った画像を拾わないようガード強化。
- 改善: 再インポート時の画像重複ダウンロードを防止。`_source_url` メタによる既ダウンロード検索を `addMediaFile` に追加し、`addThumbnail` も同経路に統一。再インポートしてもメディアライブラリが増殖しない（検証済み: 575→575件）。
- 改善: エクスポーターが出力する「グループ親列（JSON）＋子フラット列」の冗長列について、親列が存在する場合は子列を黙ってスキップ（重複インポート・警告ノイズ防止）。
- 改善: `setAttachment` で `wp_insert_attachment` 失敗（WP_Error/0）時のガードを追加。
- 改善: 画像ID解決結果を実行内キャッシュし、同じ旧IDへの重複問い合わせを排除。

### 1.0.25 (2026-06-11)

- 改善: 同一サーバー・ローカル環境内でのドメイン違いの移行時に、移行元ドメインのWordPress物理パスを自動推測し、`wp-config.php` からDB接続して画像メタデータを直接検索・アタッチメント解決する処理（`resolveLocalWpPath` / `getSourceDbConnection`）を実装しました。

### 1.0.24 (2026-06-11)
- 不具合修正: 1.0.22 以前のバージョンでの誤ったフォールバック処理により、すでにデータベースに書き込まれてしまった「柔軟コンテンツの破損データ」を安全にクリーンアップする機能を追加しました。URLに `?cleanup_acf_error=1` パラメータを付与してアクセスすることで、クリーンアップを実行し `Cannot access offset of type array` 致命的エラーを解消できます。

### 1.0.23 (2026-06-11)
- 重大な不具合修正: 1.0.22 で追加した「`update_field` が `false` を返したら `update_option`/`update_term_meta` にフォールバックする」処理が、柔軟コンテンツのデータを破壊し `Cannot access offset of type array`（致命的エラー）を引き起こしていた問題を修正。`update_field` は値が不変の場合も `false` を返すため、戻り値で失敗判定してはいけないというのが原因でした。当該フォールバックを完全に削除しました。
- 改善: フィールド名→フィールドキー（`field_xxx`）の逆引きを、`acf_get_field()` 頼みから「ACFフィールドグループ全体を走査して名前→キーのマップを構築する」確実な方式に強化（`buildFieldKeyMap`）。オプションページ／タクソノミーのコンテキストを優先し、同名フィールドの衝突にも対応。これにより柔軟コンテンツが正しく保存されない問題を解消。
- 安全対策: フィールドキーを解決できない「配列値」を生のまま ACF のメタ／オプションに書き込むとデータ構造が壊れるため、解決できない場合は書き込まずにスキップし、警告（フィールドグループ未同期の可能性）を表示するように変更。データ破損を未然に防ぎます。
- 改善: `getImportOriginDomain` をサブディレクトリ型WordPress（例: `https://example.com/dev/001_development`）に対応。指定URLをパス込みで使用し、REST API のURLが正しく組み立てられるよう修正。
- 改善: `resolveImageId` で、同一IDのアタッチメントが移行先にすでに存在する場合はそのまま採用（同一サイト・同一IDでの再インポートに対応）。
